# Code of conduct

Treat contributors and users with respect. Discuss ideas and code directly,
explain disagreements, and make room for questions and different experience
levels. Respect people's names, identities, boundaries, and privacy.

Harassment, threats, discriminatory abuse, sexualized attention, doxxing, and
deliberate disruption are unacceptable. Do not publish another person's private
information, credentials, receiver location, or private communications.

These expectations apply to project issues, pull requests, discussions, and
other spaces managed by the maintainers. They also apply when someone represents
the project publicly.

## Reporting and enforcement

For conduct concerns, use a private contact listed on a maintainer's GitHub
profile. If none is available, ask for a private contact channel without naming
people or describing the incident publicly. GitHub's report-abuse controls are
also available for activity hosted on GitHub. Use [SECURITY.md](SECURITY.md) for
software vulnerabilities.

Maintainers should handle reports discreetly, hear relevant context, and avoid
unnecessary disclosure. Responses may include removing content, a warning,
temporary restrictions, or a ban, depending on severity and repetition.
Maintainers are bound by the same expectations. A maintainer involved in a
complaint should leave its review to another maintainer where one is available;
GitHub's reporting process remains available when a project cannot resolve it.
